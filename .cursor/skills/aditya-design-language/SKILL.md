# Aditya Design Language

This website is not a generic developer portfolio.

It should feel like entering a small personal corner of the internet made by a technically serious but naturally curious person.

## Emotional identity

The site should repeatedly communicate:

- curious
- quietly stubborn
- playful
- technically serious
- honest
- human
- slightly strange
- interested in understanding why things behave the way they do

It should feel friendly rather than corporate.

It should never feel like a startup landing page.

## Core idea

The website should communicate:

"This is Aditya's little corner of the internet. Stay as long as curiosity lasts."

Do not simply print this statement as copy.

Express it through the experience.

## Human detail

The website should contain small signs that a real person made it.

Examples:

- small margin notes
- unexpected objects
- little imperfections
- tiny observations
- visual interruptions
- objects behaving strangely
- understated humor

These details should feel intentional.

## Humor

Humor should NOT become a comedy routine.

Avoid developer memes.

Avoid excessive jokes.

Prefer:

- objects getting mildly inconvenienced
- props appearing unexpectedly
- elements refusing to cooperate
- tiny handwritten observations
- honest limitations
- subtle absurdity

The humor should reward attention.

## Anti-corporate vocabulary

Prefer language such as:

- come see
- what happened next
- open it
- break something
- under the hood
- things I kept
- still figuring this one out

Avoid excessive use of:

- leveraged
- delivered value
- results-driven
- innovative
- world-class
- production-ready without proof
- high-performance without measurements

## Strong rule

Every unusual visual element must do at least one of these:

1. Reveal personality
2. Explain an idea
3. Create discovery
4. Create delight

Do not add visual novelty merely because it is technically possible.

## Anti-generic test

Before keeping a design decision ask:

"Could this exact element appear on hundreds of developer portfolios?"

If yes, reconsider it.

The site should feel authored rather than generated.
