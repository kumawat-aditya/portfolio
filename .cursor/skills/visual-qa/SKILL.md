# Visual QA

Never judge a visual interface solely from source code.

Inspect the rendered website.

## Primary objective

Determine:

"Does this feel like an exceptional creative developer portfolio?"

not merely:

"Does it compile?"

## Browser inspection

Use the browser to inspect the actual site.

Test:

- 1440px
- 1280px
- 1024px
- 768px
- 390px

## Scroll audit

Scroll through the entire homepage.

Inspect:

- section transitions
- animation timing
- object positioning
- visual rhythm
- pinned scenes
- 3D behavior
- text collisions
- unexpected overflow
- dead space

## Creative audit

Identify:

- generic layouts
- repetitive patterns
- predictable animations
- weak hierarchy
- excessive decoration
- unnecessary UI
- visually boring sections
- effects without purpose
- moments that feel AI-generated

## Personality audit

Ask:

- Does this feel human?
- Does this feel curious?
- Does the humor feel subtle?
- Does the website have personality?
- Would this still feel recognizable without the name "Aditya"?

## Mobile audit

Do not assume desktop behavior works on mobile.

Check:

- composition
- typography
- animation
- navigation
- object visibility
- overflow
- touch interaction

## Fixing strategy

Do not merely report problems.

Fix the highest-impact problems first.

Priority:

1. Broken interaction
2. Broken layout
3. Weak hierarchy
4. Generic composition
5. Poor responsive behavior
6. Accessibility
7. Performance
8. Micro-polish

## Final question

After reviewing the page ask:

"If I saw this alongside 20 other developer portfolios, would I remember it?"

If not, identify the reason and improve it.
